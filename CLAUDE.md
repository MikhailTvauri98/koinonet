# Внутренняя система церкви

Laravel API и Nuxt PWA для одной поместной церкви. Монорепозиторий: `apps/api`, `apps/web`, `infra`. Интерфейс на русском, код и идентификаторы на английском.

## Источники истины

- `docs/architecture.md`: модули, таблицы, права, процессы, API, фазы. Перед задачей читать разделы о затронутом модуле (4–7), при изменении эндпоинтов раздел 8.
- `CONTEXT.md`: словарь. Имена классов, таблиц, полей и тексты интерфейса берутся из него; новый термин сначала попадает туда.
- `docs/adr/`: необратимые решения и их причины. Читать перед изменением модели данных, прав, календаря или чата.
- `docs/plans/phase-N.md`: план текущей фазы с отметками выполненных задач. Если папки `docs/plans` нет, работа начинается с планирования фазы 1.
- Команды сборки, тестов и линтеров: `apps/api/composer.json` и `apps/web/package.json`.

## Правила, которых нет в коде

- Права проверяются ключами каталога `App\Modules\Access\Permission` через `PermissionResolver` в Policies. Роль в коде существует только как данные, её имя в условиях не встречается.
- В таблицы модуля пишут только его `Actions`. Другие модули читают модели и реагируют на доменные события слушателями в очереди.
- Записи архивируются через `archived_at`; физически удаляются только медиафайлы-сироты и данные в процедуре стирания.
- Время хранится в UTC, показывается в часовом поясе церкви из `settings`. Идентификаторы ULID.
- Установка создаёт ровно столько: настройки, роль «Администратор», первого человека с аккаунтом. Остальные роли, людей и служения админ создаёт через интерфейс.
- Каждый ключ права покрыт тестом «без права запрещено, с правом разрешено»; провайдер данных берёт ключи из каталога, поэтому новый ключ без теста роняет набор.
- Список отложенного в разделе 14 архитектуры это решения заказчика. Их реализация начинается с его явного запроса. Резервные копии закрыты окончательно: тема не поднимается ни вопросом, ни предложением.
- Изменилось решение: в том же изменении правится `docs/architecture.md` или добавляется ADR.

## Цикл работы

1. **Планирование фазы**, одна сессия. `superpowers:writing-plans` пишет `docs/plans/phase-N.md`: задачи по 1–3 часа, вертикальными срезами после скелета, у каждой файлы, критерий готовности и доказывающие тесты. Готово, когда каждая задача проверяема тестом и порядок задач учитывает зависимости.
2. **Исполнение**, одна сессия на одну задачу. Ветка `phase-N/task-M-slug`. `superpowers:subagent-driven-development` или `superpowers:executing-plans`, внутри test-first по `superpowers:test-driven-development`. Готово, когда тесты и статический анализ зелёные, документы обновлены, чекбоксы задачи отмечены в плане, коммит сделан.
3. **Завершение.** `superpowers:verification-before-completion` с реальным выводом команд, затем `/code-review` дифа против архитектуры и словаря. PR в `main`, squash.

Если репозиторий ещё не под git, `git init` входит в первую задачу скелета.
