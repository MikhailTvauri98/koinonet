# Права зашиты в код, роли настраиваются, базовой роли нет

Заказчик потребовал настраиваемую систему прав с редактором ролей на двух уровнях: глобальном и внутри служения. Принято: каталог прав это фиксированный список ключей в коде (`people.view`, `events.manage` и т. д.), а роли это данные, которые админы и лидеры собирают из этих ключей. Единственная системная роль «Администратор». Базовой роли «для всех» и ролей-заготовок при установке нет: перед приглашением человеку нужно явно выдать хотя бы одну глобальную роль.

## Рассмотренные варианты

- Фиксированный набор ролей без редактора. Отклонён заказчиком.
- Права как настраиваемые сущности. Отклонено: проверки в коде теряют смысл, если ключ права может исчезнуть.
- ACL на отдельные объекты. Отклонено: не окупается на масштабе до 1000 человек и создаёт дыры.
- Автоматическая базовая роль у каждого аккаунта и роль-заготовка при установке. Отклонены заказчиком в пользу явной выдачи ролей: кто-то должен осознанно решить, что человеку доступно, до того как он войдёт.

## Последствия

- Свежая установка содержит только роль «Администратор». Первую обычную роль админ создаёт сам.
- Человек может остаться без ролей: он увидит только всегда доступный минимум (свой профиль, свой календарь, объявления церкви, свои чаты). Это ожидаемое поведение, а не баг, который надо «починить» дефолтной ролью.
- В коде запрещены проверки по имени роли. Только ключи прав через один резолвер.
