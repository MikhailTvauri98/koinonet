# Фаза 5. Единый дизайн и адаптивный интерфейс

> Исполнение: задачи 1–2 выполнены последовательно. По прямому поручению заказчика от 01.11.2026 оставшиеся задачи выполняются агентами под координацией основного агента: отдельная рабочая копия и коммит на задачу, независимое ревью и итоговая проверка. Сначала падающая проверка, затем реализация и повторные проверки.

**Цель:** красивый, спокойный и последовательный интерфейс всех реализованных модулей, удобный на телефоне и широком экране.

**Основание:** аудит 01.11.2026 (31 маршрут, ширины 320–1440 px) и прямой запрос составить план всех исправлений и начать первую задачу. Локальный отчёт: .superpowers/verification/2026-11-01/design/design-audit.html. Все выводы перенесены ниже: план не зависит от локального отчёта.

**Архитектура:** существующие Nuxt/Vue и семантический HTML; общие CSS-токены и базовые стили, затем унификация компонентов и экранов. Серверные контракты и проверки ключей прав сохраняются. Новая UI-библиотека, внешние шрифты и CDN не нужны.

**Визуальное решение:** светлый серо-голубой фон, белые поверхности, один синий акцент, системный шрифт без засечек. Основной текст 16 px, основные текстовые поля и кнопки от 44 px; отступы 4/8/12/16/24/32/48 px. Контент оболочки до 72rem, формы до 32–40rem. Активная навигация различается фоном и текстом, фокус видим. Тени небольшие, без декоративных градиентов и анимаций.

**Выбор подхода:** общая основа с постепенным переводом модулей даёт проверяемые изменения. Точечные заплатки оставляют разнобой; полная замена UI-библиотекой добавляет зависимость и большой одномоментный риск. Конкретные значения и реализация выбраны исполнителем на основе пожеланий заказчика и аудита.

## Общие ограничения

- Задачи по 1–3 часа; один исполнитель отвечает за одну задачу. Независимые задачи допускают параллельную работу в отдельных рабочих копиях. Зависимые задачи начинаются после готовности требуемых компонентов. Координатор объединяет изменения, разрешает конфликты, ведёт план и проверяет общий результат.
- Тексты из CONTEXT.md; модули и права из docs/architecture.md, разделы 4–7, клиент — раздел 10. Отложенная функциональность не входит в фазу.
- Не скрывать дефекты общим overflow-x: hidden. Контент и действия доступны при увеличении текста. Ссылки остаются ссылками, кнопки кнопками.
- Браузерные проверки геометрии — отдельный Playwright-набор с контролируемыми ответами API, без БД и рассылок. Настоящий E2E остаётся отдельно.
- Каждая задача: профильные регрессии, npm run test -- --maxWorkers=1, npm run lint, npm run typecheck; сборка при изменении CSS/оболочки; ручной просмотр снимков.
- «Общие проверки, ревью, коммит» ниже означает эти команды, обновление затронутых решений архитектуры, проверку границ модулей, ключей прав, словаря и документов, затем коммит задачи.
- Пути app/, tests/ и конфигурации ниже указаны относительно apps/web/, кроме явно заданных docs/ и README.md.
