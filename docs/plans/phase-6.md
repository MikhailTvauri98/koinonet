Сквозные сценарии выявили зависимости от окружения: общий лимит запросов между быстрыми сценариями и отсутствие доступного каталога /media на native-раннере. Полный прогон [41328009248](https://github.com/MikhailTvauri98/koinonet/actions/runs/41328009248) успешен: api/web/e2e зелёные, 8 сценариев Playwright прошли за 2,2 минуты. Самопроверка дифа против архитектуры и словаря выполнена: границы модулей, проверки ключей прав и термины интерфейса не менялись; эксплуатационные документы обновлены.

Параллельный прогон push выявил пропуск общего beforeEach при повторном импорте fixtures из следующего файла. Причина воспроизведена отдельно: первый файл прошёл, второй упал; после переноса очистки в автоматическую фикстуру оба файла прошли. Изоляция теперь выполняется у каждого сценария независимо от кеша модулей Playwright. Финальные прогоны [PR](https://github.com/MikhailTvauri98/koinonet/actions/runs/41329576234), [push](https://github.com/MikhailTvauri98/koinonet/actions/runs/41329571844) и [CI main](https://github.com/MikhailTvauri98/koinonet/actions/runs/41330640177) прошли api/web/e2e; выкладка в последнем ещё была выключена до выпуска сертификата.

На сервере проверены nginx → API → PostgreSQL/Redis, CSRF, вход администратора, защищённая сессия и TLS WebSocket → Reverb. Для этой проверки использовался временный HTTPS только на loopback с явно доверенным тестовым сертификатом; временный контейнер, сертификат и тестовая сессия удалены. Публичный HTTPS этим не подтверждён.

HTTP-прокси проверен снаружи по серверному IP с Host домена: временный файл в /.well-known/acme-challenge вернулся с ожидаемым содержимым. Проверочный HTTP-процесс и файл удалены. Защита main требует api/web/e2e, действует для администратора и запрещает force-push/удаление; секреты SSH настроены, DEPLOY_ENABLED=false до готовности сертификата.

Пробный запуск production-образа обнаружил отсутствие пустого resources/views в чистом checkout: optimize завершался ошибкой до миграций. Каталог теперь создаётся Dockerfile; проверка настоящего entrypoint дала config/events/routes/views DONE и Laravel Framework 13.31.0. Эта проверка добавлена в workflow до переключения сервера.

## Публичный запуск 1 ноября 2026

https://koinonet-cc.ru открывается в браузере и показывает экран входа. HTTP возвращает 301 на HTTPS; проверка сертификата штатными клиентами успешна. `/api/v1/health` отвечает `{"status":"ok","database":true,"redis":true}`. Проверены CSRF, вход первого администратора, его данные, cookie Secure/HttpOnly и выход; проверочное устройство завершено. WebSocket через публичный TLS возвращает 101 и событие `pusher:connection_established`.

Продление проверено через настоящий центр Let's Encrypt: `certbot renew --force-renewal --webroot -w /var/www/certbot --no-random-sleep-on-renew` завершился `Congratulations, all renewals succeeded`; nginx перечитал сертификат. Предварительный dry-run не прошёл из-за таймаута TLS у staging-службы, поэтому его результат не выдаётся за успешную проверку. Рабочая служба выдала и продлила сертификат успешно.

После проверки HTTPS установлено `DEPLOY_ENABLED=true`. Выкладка новых коммитов main выполняется [workflow deploy](https://github.com/MikhailTvauri98/koinonet/actions/workflows/deploy.yml), который сначала повторяет все проверки и только затем обновляет контейнеры с ожиданием их здоровья. Данные входа администратора передаются отдельно от репозитория.
